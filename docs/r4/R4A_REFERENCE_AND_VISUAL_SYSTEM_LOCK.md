## Faithful-reconstruction rules

Faithfulness means preserving responsibility, hierarchy, density, and interaction consequence—not tracing a screenshot.

1. Reconstruct the Cursor-derived four-region work hierarchy with Lintel objects and language.
2. Reproduce proportions and calm density from named documentation tokens rather than copied pixel values or source styles.
3. Reproduce Vercel-like record legibility through columns, alignment, filtering, and technical typography, not through branded table chrome.
4. Reproduce incident.io-like consequence through explanations, acknowledgement, containment, and action hierarchy, not through incident vocabulary.
5. Reproduce Sana and Attio information patterns only on routes whose truthful data supports connected systems, templates, previews, or application.
6. Render StackAI-influenced relationships only when the repository supplies explicit relationships. Text similarity may not be presented as a verified link.
7. Use one consistent Lintel icon family and Lintel semantic colours. External icons and logos remain out of production.
8. Preserve current capability labels—real, configured, local, fixture, conceptual, export-only, unavailable—through every reconstruction.
9. Keep the public landing editorial and atmospheric; the logged-in application is neutral, compact, and operational.
10. Stop using the external products as production authority after R4C acceptance. The accepted R4C laboratory then becomes the visual authority.

## Patterns original to Lintel

The following are not borrowed patterns and must remain recognisably Lintel:

- `Change → Observation → Evidence → Requirement → Human Decision` as the primary review model;
- recommendation-versus-Human-Decision separation;
- risk and confidence semantics;
- missing proof as an explicit verification concern;
- evidence class, strength, provenance, run identity, commit applicability, and staleness;
- blocking and advisory requirement semantics;
- Readiness Delta and Review Diff;
- decision applicability, divergence, reaffirmation, supersession, withdrawal, and accepted-risk history;
- the canonical run manifest, reproducibility limits, result/configuration/input fingerprints, and version identity;
- a single marked GitHub comment with truthful configured/unavailable state;
- product-truth labels for local, session, durable, fixture, conceptual, and export-only records.

## Rejected product and visual patterns

R4 rejects:

- a generic metric-card dashboard as the logged-in entry;
- a default dark Workspace;
- a conventional long global sidebar;
- a Queue used as an application menu;
- a card container around every group;
- decorative colour panels;
- oversized marketing headings in the application;
- Newsreader or editorial typography in the logged-in application;
- gradients, glow, glass, heavy shadows, paper texture, cinematic lighting, and decorative illumination;
- a free-form graph, workflow builder, node editor, or relationship canvas;
- colour-only state communication;
- ubiquitous pills for ordinary labels;
- dense mono body copy or mono used as atmosphere;
- recommendation styled as approval or as a Human Decision;
- accepted risk styled as clean approval;
- fixture, inferred, conceptual, or stale data presented as current fact;
- hidden critical information on hover;
- production implementation before the R4C laboratory is accepted.

These are binding documentation tokens, not CSS custom properties or TypeScript exports. R4B maps them to component roles; R4C calibrates them visually; implementation tokens are created only in the production milestone.

### Text-contrast boundary

Meaningful compact text must begin with `color.text.important-secondary` (`#6F6F6F`) or a darker contrast-tested equivalent. `color.text.secondary` (`#8A8A8A`) and `color.text.tertiary` (`#A3A3A3`–`#B3B3B3`) must not carry essential metadata, status, instructions, or actions at compact text sizes. Those lighter values are limited to non-essential, disabled, placeholder, or structurally redundant content. R4C may darken the secondary and tertiary values to satisfy contrast without reopening the palette, hierarchy, or light application direction.

## Icon contract

R4 uses one consistent compact outline family at approximately `1.5–1.75px` stroke. Metadata and compact rows use 14px icons; navigation and standard actions use 18px; rare high-emphasis controls use 20px. Icons reinforce text and structure. Icon-only controls require accessible names and tooltips or equivalent discoverability; state, recommendation, risk, and evidence class never depend on icons alone.

## Visual acceptance

The system is accepted when it reads as a neutral, light, sustained-use engineering tool; structure comes from layout, alignment, dividers, surfaces, spacing, typography, selection, and semantic state; Lintel's evidence and authority model is visually dominant; and no borrowed pattern can be mistaken for copied branding or unsupported capability.
